# 启发式可用性测试报告

日期：2026-06-12 ｜ 被测对象：DesignAgent（localhost:3100，M1 完成态）
方法：端到端真实操作（桌面 1440px / 移动 375px），关键路径全覆盖 + 后端状态核对

## 高严重度

### H1. 首页发起任务后，画布"失联"（核心路径断裂）
复现：首页输入"给我的咖啡品牌做 2 张小红书封面图"→ 发送 → 跳转画布。
结果：聊天区只有欢迎语，无用户消息、无计划卡片；但后端确认任务已创建且处于 awaiting_approval。
用户感知：输入被吞了，什么都没发生；任务在后台静默挂到 10 分钟超时。
根因链：① 首页 POST /chat 后跳转，消息历史未持久化（messages_snapshot 不落库）；② 画布加载时不恢复 in-flight 任务的事件流；③ ?q= 参数消费逻辑与已发请求叠加。
建议：首页只负责"创建会话 + 带参跳转"，发送动作统一由画布执行；画布加载时拉取 GET /sessions/{id}/jobs，对非终态任务自动恢复轮询并重建 UI（含审批卡片）。

### H2. 同一动作产生重复任务（计费风险）
复现：同一条输入在同一会话产生了 2 个 job（首页 POST + 画布 ?q= 自动发送叠加；用户连点发送也可触发）。
后果：接入真实计费后会双倍扣费、双倍生成。
建议：前端发送中置 disabled + in-flight 守卫；后端 /chat 加幂等键（如 client_request_id），相同键直接返回已有 job_id。

### H3. 等待审批的任务在刷新/重进后不可见不可操作
复现：计划卡片出现后刷新页面 → 卡片消失，任务仍在后台等审批，无任何入口找回。
建议：与 H1 同源修复（恢复非终态任务）；审批卡片显示有效期倒计时；超时后在聊天流追加"计划已过期，重新发起"提示。

### H4. 移动端布局破碎
- 首页 hero 文案逐词竖排（"Design is easier with" 一列 + "Agents" 悬浮右侧），第一屏即破相
- 画布页：画布被挤成左侧约 50px 的窄条，无法操作，也没有画布/聊天的显式切换；顶部返回按钮被裁切
建议：hero 容器改 flex-wrap/块级布局；移动端默认全屏聊天 + 底部 tab 切换画布；画布操作（缩放/拖动）做触屏适配验证。

## 中严重度

### M1. 余额展示不一致且无去向
首页 Navbar 显示 `CREDITS 370`，画布页头显示 `$ 370`——同一数值两种语义（美元符号会让用户以为是钱包余额）。徽标不可点击，无 tooltip、无"什么是积分/怎么获取"的入口。
建议：统一为 CREDITS 表述；点击进入用量明细页（M3 计费页的入口预留）。

### M2. 会话全部叫 "Untitled"
7 个项目全名 Untitled，两个缩略图几乎一样时无法区分；重命名入口隐蔽。
建议：用首条 brief 截断自动命名（后端创建 job 时顺手 PATCH session.name），支持卡片上直接改名。

### M3. 品牌泄漏与文案错位
- VIEW SOURCE 按钮链接到上游 fork 仓库（Anil-matcha/Open-Lovart）
- 副标题 "The open-source design agent…" 与产品定位（电商/Logo/自媒体的商业 SaaS）不符
- 浏览器标题中英混排："Design Agent — AI 设计工作台"
- 画布页眉仍是 "CREATIVE AGENT / Design Agent Studio" 旧品牌
建议：M4 落地页前统一品牌词；首屏文案改为垂直场景价值主张 + 三个场景的示例入口。

### M4. 界面语言混杂
UI 文案全英文，Agent 回复中文（"完成：成功生成 2 张"），错误 toast 英文。对国内用户首屏全英文有门槛，对海外用户 Agent 中文回复是缺陷。
建议：M2 的 next-intl 落地时把后端事件文案也纳入（事件存 key + 参数，前端按 locale 渲染）。

### M5. 长任务反馈不足
生图 35-75s、编辑约 3 分钟，期间只有卡片 spinner：无进度感、无预计耗时、无排队位置；超过 6 分钟前端直接停止轮询（MAX_DEAD_AIR）且无提示。
建议：tool_call 事件附带预计耗时（按模型统计的 P50）；卡片显示已等待时间；dead-air 停止时给出"仍在后台运行，点击恢复"的操作。

### M6. 删除会话用原生 window.confirm
与整体视觉割裂，且无撤销。
建议：自定义确认对话框（设计体系内）+ 软删除支持撤销（后端已是软删除，只差前端 toast 撤销按钮）。

## 低严重度

- L1. 1 个图标按钮无 aria-label/title；上传、技能图标含义靠猜（建议 hover tooltip）
- L2. 8-10px 微字号 + text-gray-600 on #09090b 的组合对比度处于 WCAG AA 边缘，长文场景慎用
- L3. 空画布欢迎语 "Session ready — what shall we create?" 是死胡同：应给 3 个垂直场景的一键示例（电商主图/Logo/小红书封面）降低首次使用门槛
- L4. 发送按钮空输入时有视觉置灰但语义上 disabled 属性缺失（键盘/读屏用户会困惑）
- L5. 无 favicon、无 404 页定制

## 做得好的（保持）

- 画布内的"计划→审批→逐卡片出图"流程清晰，事件卡片的实时反馈节奏好
- 编辑结果自动放源图旁，对比式工作流直觉正确
- 刷新后画布布局完整恢复（本次迭代修复）
- 跨页面样式一致性（本次迭代修复）
- 暗色工业风视觉气质统一，层级清楚

## 建议修复顺序

1. H1+H2+H3 同一根源（任务状态恢复 + 幂等），一次性修，这是商业化前的硬门槛
2. H4 移动端 hero（小改）；画布移动端体验可放到 M2 后
3. M1/M2/M6 是小工作量高感知收益，适合穿插做
4. M3/M4 并入 M4 落地页与 i18n 计划
